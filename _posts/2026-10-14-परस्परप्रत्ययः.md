<details>
<summary>English · overview and topics (minimizable)</summary>
<div class="prose-text" markdown="1">

### What this post is about
**mTLS** authenticates both sides of a connection with certificates so east-west traffic carries workload identity.

### Topics covered
1. Beyond network-location trust  
2. Client + server certificates  
3. Automated issuance (SPIFFE-class)  
4. Mesh sidecar vs in-app TLS  
5. Expiry monitoring  
6. Identity is not authorization  
7. Rotation overlap windows  
8. Trust bundle distribution  
9. Narrow plaintext exceptions  
10. Zero-trust link  

### Sanskrit title
**परस्परप्रत्ययः** = *paraspara-pratyayaḥ* "mutual trust/authentication".

### English
Minimizable; Sanskrit-first.

<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **both certs verified**: client+server  
२. **auto rotate**: short-lived workload certs  
३. **overlap window**: accept N and N+1  
४. **trust bundle sync**: all nodes  
५. **authz layer**: allow by identity  
६. **expiry alerts**: client and server  
७. **choose one plane**: mesh or app not accidental double  

### त्याज्यम् / Avoid
- trust flat VPC alone  
- manual yearly client certs as only process  
- mTLS without authorization policy
