**मुखसेवा** is a client-family face that aggregates and shapes backend calls for one UI without becoming a second monolith.

2. Family not per-screen  
3. Shape do not leak the core  
4. Budgeted fan-in  
5. Session at the face  
6. Keep it thin  
7. Walk with the client train  
8. Keyed caches  
9. Trace each hop  
10. Gateway versus face versus strangler  
11. Five limbs  
12. Close

<summary>ग्राह्य-त्याज्य-विवेकः / Keep and avoid</summary>
<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **one BFF per client family**: not per screen  
२. **shape payloads for that UI**: no raw domain dump  
३. **parallel fan-in under a parent deadline**: no waterfall  
४. **session translation at the face**: core speaks service identity  
५. **keep deep invariants downstream**: thin face  
६. **compat for slow mobile trains**: version gates  
७. **cache only with auth and tenant keys**: no mix  
८. **trace each downstream hop**: not only face p99  

### त्याज्यम् / Avoid
- one public door forcing many mobile round trips  
- a face that owns all money invariants forever  
- an anonymous shared cache of personalized graphs
