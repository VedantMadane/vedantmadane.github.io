### What this post is about
**API keys** are shared secrets for machine clients. They need the same lifecycle discipline as other credentials.

### Topics covered
1. Machine auth use case  
2. Show-once + hash at rest  
3. Scoped keys and env split  
4. Zero-downtime rotation  
5. Per-key rate limits  
6. Leak scanning and revoke  
7. Owner and last-used inventory  
8. Not for SPAs  
9. Audit events  
10. Links to secrets sessions OAuth  

### Sanskrit title
**कुञ्जीप्रबन्धनम्** = *kuñjī-prabandhanam* "key management".

### English
Minimizable; Sanskrit-first.

<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **hash at rest**: no retrieve plaintext  
२. **narrow scopes**: env separated  
३. **overlap rotation**: two keys valid  
४. **per-key limits**: noisy integration fence  
५. **inventory**: owner last_used  
६. **fast revoke**: runbook  
७. **no keys in frontend**: use user tokens  

### त्याज्यम् / Avoid
- store API keys in git  
- one production key for all partners  
- no revoke path
