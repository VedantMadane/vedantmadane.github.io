### What this post is about
**Optimistic concurrency control (OCC)** detects lost updates with versions/ETags instead of long-held locks.

### Topics covered
1. Lost updates  
2. Version column + conditional UPDATE  
3. HTTP ETag / If-Match  
4. 409 Conflict responses  
5. OCC vs pessimistic locks  
6. Document revisions / CAS  
7. Batch item versions  
8. Client merge UX  
9. Conflict-rate metrics  
10. OCC vs idempotency keys  

### Sanskrit title
**आशावादीबन्धः** = *āśāvādī-bandhaḥ* "optimistic binding/lock".

### English
Minimizable; Sanskrit-first.

१. **versionस्तम्भः**: monotonic per row  
२. **conditional write**: WHERE version / If-Match  
३. **409स्पश**: conflict with reload hint  
४. **ETag expose**: on readable resources  
५. **merge UX**: show both sides  
६. **conflict metrics**: tune hot resources  
७. **short OCC**: small documents prefer OCC  

### त्याज्यम् / Avoid

- PUT without If-Match on shared docs  
- ignore 0-row updates as success
