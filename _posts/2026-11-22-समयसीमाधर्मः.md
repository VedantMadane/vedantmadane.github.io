<details>
<summary>English · overview and topics (minimizable)</summary>
<div class="prose-text" markdown="1">

### What this post is about
**Deadline propagation** carries a single user time budget through every service hop with cancellation when the budget or client dies.

### Topics covered
1. Root budget must flow down  
2. Absolute vs stacked relatives  
3. Cancel orphan work  
4. Child inside remaining parent  
5. Wire deadline headers  
6. Queue wait is user time  
7. Distinct timeout error class  
8. Retries and hedges share purse  
9. No infinite server defaults  
10. Breaker hedge and deadline roles  

### Sanskrit title
**समयसीमाधर्मः** = *samaya-sīmā-dharmaḥ* "dharma of the time limit".

### English
Minimizable; Sanskrit-first.

### ग्राह्यम् / Keep
१. **pass absolute end or remaining**: not fresh +N each hop  
२. **cancel children on parent death**: no orphans  
३. **child timeout < remainder**: always  
४. **preserve deadline on the wire**: standard headers  
५. **count queue wait**: in user budget  
६. **label deadline exceeds**: distinct from 500  
७. **one purse for retry/hedge**: no full reset each try  

### त्याज्यम् / Avoid
- stack +5s timeout per hop by default  
- ignore client disconnect and finish heavy work  
- give each retry a brand new full 30s
