### What this post is about
**Read-your-writes** guarantees that a client sees its own successful updates on subsequent reads despite replica lag and caches.

### Topics covered
1. Stale self after write  
2. Sticky primary sessions  
3. Version tokens  
4. Cache and CDN coherence  
5. Session vs cross-device scope  
6. Offline optimistic echo  
7. Multi-region sticky paths  
8. Stale-self UX metrics  
9. Not full linearizability  
10. Isolation vs RYW vs replicas  

### Sanskrit title
**स्वलेखपठनधर्मः** = *sva-lekha-paṭhana-dharmaḥ* "dharma of reading one's own writing".

<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **sticky route after write**: primary or caught-up  
२. **return version watermarks**: honor on read  
३. **invalidate/version caches**: user will hit  
४. **promise RYW in-session first**: document cross-device  
५. **reconcile offline echoes**: with server ack  
६. **region-sticky after geo write**: no instant global myth  
७. **metric stale-self rate**: UX SLO  

### त्याज्यम् / Avoid
- load-balance next read randomly right after write  
- CDN cache profile page without bust on edit  
- claim linearizability while only doing RYW sticky
