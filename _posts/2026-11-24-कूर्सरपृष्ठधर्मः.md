### What this post is about
**Cursor pagination** continues a result set from a stable sort-key token instead of OFFSET page numbers that drift and slow down.

### Topics covered
1. Offset drift problem  
2. Keyset cursor shape  
3. Stable total order  
4. Opaque signed tokens  
5. Forward and backward  
6. Deletes between pages  
7. NULL ordering rules  
8. Server page size caps  
9. has_more vs COUNT  
10. Batch API and index links  

### Sanskrit title
**कूर्सरपृष्ठधर्मः** = *kūrsar-pṛṣṭha-dharmaḥ* "dharma of cursor pages".

### English

<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **keyset + unique tie break**: not deep offset  
२. **stable deterministic sort**: required  
३. **opaque signed cursors**: no raw SQL  
४. **cap page size server-side**: always  
५. **document live-data holes**: deletes  
६. **explicit NULL order**: encode match  
७. **prefer has_more**: over COUNT each page  

### त्याज्यम् / Avoid
- OFFSET 100000 for every infinite scroll tick  
- put SQL fragments in client cursors  
- allow limit=1000000 from any client
