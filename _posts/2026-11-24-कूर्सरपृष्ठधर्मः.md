### What this post is about
**Cursor pagination** continues a result set from a stable sort-key token. Offset page numbers drift under inserts and force the database to walk and discard ever more rows.

### Topics
1. Offset drift problem  
2. Keyset cursor shape  
3. Stable total order  
4. Opaque signed tokens  
5. Forward and backward  
6. Deletes between pages  
7. NULL ordering rules  
8. Server page size caps  
9. has_more versus exact count  
10. Batch API and index links  
11. Five limbs  
12. Close  

English minimizable. Pure padya. Title keeps कूर्सर; verses prefer स्थिराङ्क.

<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **keyset plus unique tie break**: not deep offset  
२. **stable deterministic sort**: required  
३. **opaque signed cursors**: no raw query fragments  
४. **cap page size server-side**: always  
५. **document live-data holes**: deletes  
६. **explicit null order**: encode match  
७. **prefer has_more**: over exact count each page  

### त्याज्यम् / Avoid
- deep offset for every infinite-scroll tick  
- put query fragments in client cursors  
- allow huge page sizes from any client
