### What this post is about
**Query plan regression** is a silent performance failure when the optimizer switches to a worse access path without an application code change.

### Topics covered
1. Slow without a deploy  
2. Baseline critical plans  
3. Stats and histograms  
4. Sparse freezes and hints  
5. CI on realistic data  
6. Examined-row early alerts  
7. Migration plan review  
8. Parameter sniffing  
9. Paired SQL ownership  
10. Index vs planner vs shard  

### Sanskrit title
**प्रश्नयोजनाधर्मः** = *praśna-yojanā-dharmaḥ* "dharma of the query plan".

### English

१. **baseline EXPLAIN for money queries**: versioned  
२. **keep stats fresh after bulk load**: histograms  
३. **pin plans sparingly**: not hint litter  
४. **CI plan checks on realistic volumes**: not empty DB  
५. **alert on examined rows/IO spikes**: before p99 only  
६. **review plans on index drop/migrate**: expand-contract  
७. **name app+data owners per critical SQL**: page route  

### त्याज्यम् / Avoid

- trust EXPLAIN on empty staging tables only  
- no owner for the checkout SELECT that pays the bills
