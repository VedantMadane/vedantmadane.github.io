5. Bake time per step
6. Shared store and schema risk
7. Staff force path

9. Progressive ladders

### ग्राह्यम् / Keep
१. **sticky cohorts**: stable user assignment  
२. **compare to live baseline**: not only history  
३. **bake each step**: enough wall time  
४. **auto rollback**: on budget burn  
५. **expand-contract schemas**: shared stores  
६. **watch checkout signals**: not only machine faults  
७. **publish ladders**: risk-tuned  

### त्याज्यम् / Avoid
- jump from none to half with no bake  
- new app while breaking a shared schema  
- ignore funnel metrics when machines look green
