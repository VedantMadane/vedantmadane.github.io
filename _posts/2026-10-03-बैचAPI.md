### What this post is about
A **batch API** accepts many ids or operations in one request to cut chattiness. It needs strict bounds and per-item results.

### Topics
1. Chatty client problem
2. Hard size cap
3. Per-item results
4. Per-item keys
5. Order and parallelism
6. Atomic versus best-effort
7. Rate cost
8. Large work becomes a job
9. Per-item authorization
10. Pagination versus batch
11. Five limbs
12. Close

<summary>ग्राह्य-त्याज्य-विवेकः / Keep and avoid</summary>
<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **hard max items**: always  
२. **per-item result objects**: not one boolean  
३. **idempotency per item**: safe retry  
४. **document order or parallel**: no surprise  
५. **say the rate cost**: one versus N  
६. **huge imports become jobs**: not long holds  
७. **authorize each id**: no cross-tenant leak  

### त्याज्यम् / Avoid
- unbounded batch arrays  
- single boolean success for a side-effecting batch  
- retry the whole batch without item keys
