<details>
<summary>English overview · Context and topics</summary>
<div class="prose-text" markdown="1">

### What this post is about
A **batch API** accepts many ids or operations in one HTTP request to cut chattiness. It needs strict bounds and per-item results.

### Topics covered
1. N+1 / chatty client problem  
2. Max batch size  
3. Partial success responses  
4. Per-item idempotency  
5. Ordering and parallelism  
6. Atomic vs best-effort  
7. Rate-limit accounting  
8. Sync small vs async large  
9. Per-item authorization  
10. Link to pagination  

### Sanskrit title
**बैचAPI** keeps the loanword *batch* with API; the dharma is measured grouping of work.

### ग्राह्यम् / Keep
१. **कठोरसीमा**: max items  
२. **प्रतिमदउत्तरम्**: per-item result objects  
३. **मदकुञ्चिका**: idempotency per item  
४. **क्रमघोषणा**: order/parallel documented  
५. **दरस्पष्टता**: 1 vs N rate cost  
६. **बृहत्जॉब्**: large batches become jobs  
७. **प्रतिमदाधिकारः**: authz each id  

### त्याज्यम् / Avoid
- unbounded batch arrays  
- single boolean success for whole batch with side effects  
- retry whole batch without item keys
