<details>
<summary>English · overview and topics (minimizable)</summary>
<div class="prose-text" markdown="1">

### What this post is about
A **sidecar** is a colocated helper container/process that implements shared platform concerns beside the app.

### Topics covered
1. Cross-cutting without every language rewrite  
2. Shared birth/death order  
3. Resource accounting for both containers  
4. Blast radius of proxy bugs  
5. Typical duties (mTLS metrics)  
6. Admin interface exposure  
7. App/sidecar version skew  
8. Fail open vs closed  
9. Operate the sidecar itself  
10. Gateway vs sidecar planes  

### Sanskrit title
**पार्श्वयानधर्मः** = *pārśva-yāna-dharmaḥ* "dharma of the side-vehicle / sidecar".

### English
Minimizable; Sanskrit-first.

### ग्राह्यम् / Keep
१. **defined start/stop**: and volume shares  
२. **request sum**: app+sidecar  
३. **canary proxy upgrades**: mesh rollouts  
४. **localhost admin**: not LAN open  
५. **compat matrix**: app vs proxy versions  
६. **explicit fail mode**: open vs closed  
७. **sidecar SLOs**: cpu restarts cert age  

### त्याज्यम् / Avoid
- forget sidecar memory in capacity plans  
- one bad proxy to 100 percent fleet with no canary  
- expose envoy admin to the pod network
