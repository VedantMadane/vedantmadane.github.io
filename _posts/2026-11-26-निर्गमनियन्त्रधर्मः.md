### What this post is about
**Egress control** restricts outbound network paths from workloads so compromise and SSRF cannot freely reach the world or cloud metadata.

### Topics covered
1. Open egress as leak path  
2. Default deny  
3. FQDN over raw IP  
4. Scoped allow classes  
5. Log denies  
6. CI vs runtime width  
7. Block metadata ranges  
8. Expiring exceptions  
9. Mesh and host layers  
10. Webhook vs egress vs mTLS  

### Sanskrit title
**निर्गमनियन्त्रधर्मः** = *nirgama-niyantra-dharmaḥ* "dharma of controlling exit".

### English
Minimizable; Sanskrit-first.

### ग्राह्यम् / Keep
१. **default deny egress**: allowlist only  
२. **FQDN policies preferred**: over brittle IPs  
३. **separate CI and runtime**: allows  
४. **block metadata/link-local**: explicitly  
५. **log and alert denies**: compromise signal  
६. **break-glass with expiry**: no permanent holes  
७. **layer mesh + node filters**: defense depth  

### त्याज्यम् / Avoid
- default-allow all egress in prod  
- copy CI npm registry allows into payment runtime  
- no block on cloud metadata IP from apps
