### What this post is about
**Egress control** restricts outbound network paths from workloads so compromise and server-side request forgery cannot freely reach the world or cloud metadata.

### Topics
1. Open egress as leak path  
2. Default deny  
3. Names over raw numbers  
4. Scoped allow classes  
5. Log denies  
6. Build versus runtime width  
7. Block metadata ranges  
8. Expiring exceptions  
9. Mesh and host layers  
10. Webhook versus egress versus mutual proof  
11. Five limbs  
12. Close  

English minimizable. Pure padya.

१. **default deny egress**: allowlist only  
२. **name policies preferred**: over brittle numbers

४. **block metadata and link-local**: explicitly  
५. **log and alert denies**: compromise signal  
६. **break-glass with expiry**: no permanent holes  
७. **layer mesh and node filters**: defense depth  

### त्याज्यम् / Avoid

- copy build registry allows into payment runtime

| संस्कृतपदम् | Word-for-word English |

**English sense**  
Egress control limits which external hosts and ports workloads may reach so stolen code cannot freely exfiltrate or forge requests into the cloud. Ingress authz does not see outbound. Browser headers do not see server outbound. This is a different door.
