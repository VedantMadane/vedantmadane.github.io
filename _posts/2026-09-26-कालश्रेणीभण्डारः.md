### What this post is about
A **time-series database** (or TS-optimized metrics backend) stores timestamped measurements for dashboards, SLOs and alerts.

### Topics covered
1. Why general OLTP stores struggle with metrics  
2. Series model: name, labels, time, value  
3. Cardinality explosions  
4. Append-heavy write vs windowed read  
5. Downsampling and rollups  
6. Retention by class  
7. Batched remote write  
8. Recording rules / read governance  
9. Timestamp and skew  
10. Stable names for paging metrics  
11. Link to observability treatise  

### Sanskrit title
**कालश्रेणीभण्डारः** = *kāla-śreṇī-bhaṇḍāraḥ* "store of time-series".

### ग्राह्यम् / Keep
१. **टैगसीमा**: deny high-cardinality label keys  
२. **उष्णशीतधारणम्**: hot raw cold rollup  
३. **बैचलेखनम्**: batched compressed write  
४. **recording**: precompute hot queries  
५. **नामस्थिरता**: alert metrics rarely rename  
६. **घडीनीतिः**: document timestamp source  
७. **मापनं स्वस्य**: monitor the TSDB itself  

### त्याज्यम् / Avoid
- user_id label on every request metric  
- infinite raw retention by default  
- dashboard queries that scan everything without bound
