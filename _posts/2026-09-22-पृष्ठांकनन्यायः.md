<details>
<summary>English overview · Context and topics</summary>
<div class="prose-text" markdown="1">

### What this post is about
**Pagination** is how an API returns a large collection in **bounded pages** instead of one giant array.

### Topics covered
1. Why unbounded lists hurt servers and clients  
2. Offset/page-number vs cursor/keyset pagination  
3. Deterministic sort order as contract  
4. Max page size  
5. Response fields: items, next_cursor, has_more, optional total  
6. Opaque cursors (security)  
7. Deletes and bidirectional scroll  
8. Links to rate limits and retries  

### Who should read
API designers, mobile and web client authors, backend engineers owning list endpoints.

### Sanskrit note
Title **पृष्ठांकनन्यायः** = *pṛṣṭhāṅkana-nyāyaḥ* roughly "the rule/method of page-marking".

<summary>ग्राह्य-त्याज्य-विवेकः / Keep and avoid</summary>
<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **मितपृष्ठम्**: hard max page size  
२. **कुञ्चिकापथः**: prefer cursor/keyset for large changing data  
३. **क्रमसत्यम्**: document sort keys  
४. **अपारकुञ्चिका**: opaque cursor tokens  
५. **has_more**: clear end signal  
६. **गणनाविवेकः**: total count only when cheap or needed  
७. **इदमर्थपठनम्**: list GET safe to retry  

### त्याज्यम् / Avoid
- return entire table by default  
- client-built SQL in cursor  
- offset deep page on huge tables as only option
