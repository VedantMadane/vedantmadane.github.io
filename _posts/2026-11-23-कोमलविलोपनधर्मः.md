### What this post is about
**Soft deletes** mark records deleted without immediate physical removal so undo audit and controlled purge remain possible.

### Topics covered
1. Mark vs hard remove  
2. Default query filters  
3. Unique keys and recreate  
4. Cascade policy  
5. Retention then hard purge  
6. Erasure beyond soft flags  
7. Cache and search invalidation  
8. Tested restore  
9. Audit actor fields  
10. Event tombstone vs row soft vs WAL  

### Sanskrit title
**कोमलविलोपनधर्मः** = *komala-vilopana-dharmaḥ* "dharma of gentle erasure".

### English
Minimizable; Sanskrit-first.

### ग्राह्यम् / Keep
१. **filter deleted by default**: admin opt-in  
२. **design uniques for recreate**: partial indexes  
३. **explicit cascade policy**: no ghost children  
४. **timed hard purge**: no forever graveyard  
५. **erasure path hard/crypto**: when law requires  
६. **invalidate search/cache**: on soft delete  
७. **test restore end-to-end**: with audit fields  

### त्याज्यम् / Avoid
- leave soft-deleted rows in normal user lists  
- soft-only forever for GDPR erasure requests  
- undelete button never tested on children
