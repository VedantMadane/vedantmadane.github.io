<details>

### What this post is about
The **transactional outbox** avoids dual-write bugs by storing outbound events in the same DB transaction as the business update then publishing them with a relay.

### Topics covered
1. Dual-write failure mode  
2. Same-transaction outbox rows  
3. Relay publisher  
4. pending/sent/failed states  
5. Ordering via keys  
6. Poison rows  
7. Lag metrics  
8. Purge retention  
9. Consumer inbox idempotency  
10. Link to message queues  

### Sanskrit title
**बहिर्लेखनपटलः** = *bahir-lekhana-paṭalaḥ* "tablet/surface for outward writing" (outbox).

| संस्कृतपदम् | Word-for-word English |
| :---- | :---- |
| द्विलेखने | in dual-write |
| यदि | if |
| एकम् | one |

**English sense**  
Writing the database and then separately publishing to a queue can leave one side done and the other not. The outbox pattern writes the business row and an outbox row in one transaction then publishes asynchronously.
