<details>
<summary>English · overview and topics (minimizable)</summary>
<div class="prose-text" markdown="1">

### What this post is about
**Sessions** persist authentication across requests using server state and/or tokens with careful lifecycle and browser storage rules.

### Topics covered
1. Why sessions  
2. High-entropy session ids  
3. Idle and absolute timeouts  
4. Cookie flags vs JS storage  
5. Session fixation / rotate on login  
6. Server-side logout  
7. Multi-device revoke  
8. CSRF  
9. Access/refresh token pattern  
10. Link to IAM  

### Sanskrit title
**सत्रधर्मः** = *satra-dharmaḥ* "dharma of the session".

<summary>ग्राह्य-त्याज्य-विवेकः / Keep and avoid</summary>
<div class="prose-text" markdown="1">

### ग्राह्यम् / Keep
१. **दृढID**: unpredictable session id  
२. **द्विकालसीमा**: idle + absolute  
३. **HttpOnlySecure**: hardened cookies  
४. **loginजन्म**: rotate id on login  
५. **सर्वरवधः**: invalidate server-side  
६. **यन्त्रसूची**: list/revoke devices  
७. **CSRF रक्ष**: state-changing CSRF defense  

### त्याज्यम् / Avoid
- guessable session ids  
- logout only clears client cookie  
- infinite access tokens in localStorage as only plan
