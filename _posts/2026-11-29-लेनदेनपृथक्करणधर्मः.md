### What this post is about
**Transaction isolation** bounds which concurrent database effects a transaction may observe and which anomalies it refuses.

### Topics covered
1. Unnamed defaults hurt  
2. Ladder RU RC RR SI SER  
3. RR vs snapshot quirks  
4. Serializable cost  
5. Anomaly vocabulary  
6. Explicit begin on pools  
7. Short write transactions  
8. Retry serialization fails  
9. Replica weaker reads  
10. Saga vs isolation vs row locks

### ग्राह्यम् / Keep
१. **name isolation per critical path**: engine-true  
२. **catalog refused anomalies**: dirty phantom skew  
३. **set level at txn begin**: no pool sticky leak  
४. **keep write TX short**: no remote in TX  
५. **retry serialization aborts**: with budget  
६. **do not assume primary isolation on replicas**: lag  
७. **serializable only where invariants need**: not fashion  

### त्याज्यम् / Avoid
- rely on default isolation never documented  
- open write txn around HTTP fan-out  
- treat replica read as serializable primary
