**Transaction isolation** bounds which concurrent database effects a transaction may observe and which anomalies it refuses. It is one-store concurrency control not a cross-service saga.

5. Anomaly vocabulary  
6. Explicit begin on pools  
7. Short write transactions  
8. Retry serialization fails

10. Saga versus isolation versus row locks

### ग्राह्यम् / Keep
१. **name isolation per critical path**: engine-true  
२. **catalog refused anomalies**: dirty phantom skew  
३. **set level at transaction begin**: no pool sticky leak  
४. **keep write transactions short**: no remote call inside  
५. **retry serialization aborts**: with budget  
६. **do not assume primary isolation on replicas**: lag  
७. **serializable only where invariants need it**: not fashion  

### त्याज्यम् / Avoid
- rely on default isolation never documented  
- open a write transaction around a remote fan-out  
- treat a replica read as serializable primary
