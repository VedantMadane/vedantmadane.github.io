### What this post is about
A **connection pool** holds reusable network sessions (to Postgres, Redis, HTTP upstreams) so each request does not pay a full handshake.

### Topics covered
1. Cost of connect-per-request  
2. Min/max pool size  
3. Checkout/acquire timeout  
4. Validation and keepalives  
5. Leak-free release  
6. Separate pools (bulkheads)  
7. Metrics  
8. Autoscaling times max_connections  
9. Ties to timeouts and circuit breakers  

### Sanskrit title
**सम्बन्धकुण्डधर्मः** = *sambandha-kuṇḍa-dharmaḥ* "dharma of the connection-reservoir".

३. **स्वास्थ्यम्**: validate dead conns

| संस्कृतपदम् | Word-for-word English |
| :---- | :---- |
| कालसीमा | timeout |
| योगे | on connection/query |
| बध्नाति | binds |

| भङ्गिरोधः | breaker |

**English sense**  
Timeouts free pooled connections stuck on slow queries. Breakers stop the pool from hammering a dead DB. The pool is the seat where both apply.
