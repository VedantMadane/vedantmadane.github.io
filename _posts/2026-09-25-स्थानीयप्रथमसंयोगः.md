<details>
<summary>English · overview and topics (minimizable)</summary>
<div class="prose-text" markdown="1">

### What this post is about
**Local-first** software keeps a usable local replica so users can work offline or on flaky networks, then synchronizes with merge rules.

### Topics covered
1. Offline availability goal  
2. Local truth before server round-trip  
3. Conflict policies (LWW, CRDT, manual)  
4. Ordered local op logs  
5. Idempotent sync mutations  
6. Encrypt local stores  
7. Visible pending/synced/conflict UX  
8. Device storage budgets  
9. Incremental change feeds  
10. Multi-tenant isolation on device  

### Sanskrit title
**स्थानीयप्रथमसंयोगः** = *sthānīya-prathama-saṃyogaḥ* "connection/sync that is local-first".

### ग्राह्यम् / Keep
१. **स्थानीयलेखः**: durable local store  
२. **मेलनन्यायः**: documented conflict policy  
३. **उपकरणपङ्क्तिः**: local mutation log  
४. **इदमर्थमेलनम्**: mutation ids on sync  
५. **उपकरणगोप्यता**: encrypt at rest  
६. **संकेतUI**: pending/conflict markers  
७. **आकारसीमा**: evict local caches  

### त्याज्यम् / Avoid
- block all UI on network  
- silent LWW on critical data  
- plaintext secrets in IndexedDB/SQLite by default
